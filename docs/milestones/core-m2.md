# Core M2: IR, XML, and Persistence

## Implemented Contract

The core exposes an IR `schemaVersion: 1` for Ipe XML `70218`, validated with Zod and stable structural diagnostics. Pages, layers, views, and objects remain separate entities; `Page.objects` is the sole global z-order sequence. On import, an object without an identity receives a deterministic, unique `custom="ipe-mcp:<uuid>"` in the IR; every object and every page, layer, view, stylesheet, and asset also receives a server-owned `x-ipe-mcp-id`, materialized in the working copy on first serialization and in the source only on `save`. Server-owned IDs have typed formats and global uniqueness; page, stylesheet, and asset payloads follow their respective entities during reordering. IDs and references therefore remain stable after renames, edits, and reordering without depending on a name, XML index, or mutable payload. An object built directly in the IR must provide a canonical `object-<hash24>` ID and a `custom`; `objectIdFromCustom()` remains a convenience constructor, not a constraint, because `custom` is mutable metadata and the authoritative identity is `x-ipe-mcp-id`. Existing `custom` values remain lossless: historical duplicates are preserved and reported as warnings, while the server-owned ID disambiguates them without rewriting them.

The XML boundary uses Saxes without namespaces and without resolving DTDs or named entities. It accepts only Ipe's optional canonical doctype, UTF-8, and safe numeric references; it applies byte, depth, node, and attribute limits while reading, bounded by a single file handle. Absent matrices use Ipe defaults, while present but malformed or degenerate matrices fail explicitly. The serializer orders attributes deterministically, makes layer/view/marked explicit, and preserves payloads, `custom`, `x-*`, stylesheets, bitmaps, unknown elements, and object order. XML comments and processing instructions have no Ipe semantics and are unsupported.

The structural changes currently serialized by the IR are metadata/preamble, page attributes (including `marked`), layers (`name`, `edit`, `snap`), views and transforms, object ordering/removal, and common attributes (`layer`, `custom`, `matrix`, `pin`, `transformations`). `locked` and `snapping` remain compatibility aliases for the inverse of `edit` and for `snap=never|visible`, respectively; native Ipe fields `edit` and `snap` take precedence. A new object already requires its own valid XML payload; typed primitive compilation belongs to M4, and a missing payload produces an error rather than silent loss.

## Sessions and Saving

`DocumentSessionManager` opens a working copy under an allowlisted root and maintains a monotonic revision. Every batch requires `expectedRevision`, operates on a clone, validates before commit, and publishes an immutable working copy together with an atomic manifest. `recover()` reloads unsaved revisions after a restart; snapshots are enumerable, receive an atomic CAS sequence shared across processes, and `restoreSnapshot()` promotes the selected snapshot (the newest by default) to a new revision without touching the source. The source remains byte-identical until `save`; save rechecks the file's hash and identity under a shared filesystem lock immediately before rename, creates a snapshot, writes a temporary file in the same directory, runs `fsync`, renames, and `fsync`s the directory. A persistent journal distinguishes commits not started from renames already completed even if durability confirmation or subsequent manifest publication fails. Deletions, replacements, and concurrent saves between managers/processes are conflicts. External paths and symlinks escaping the roots are rejected, including symlink insertion during the window between allowlisting and target reading.

The optional sidecar has a strict v1 schema and deterministic migration from v0. The `.ipe` does not depend on the sidecar.

## Gate and Native Boundary

`bash scripts/gates/check-m2.sh` reruns M0/M1, builds and tests M2, then verifies the 12 M0/M1/M2 fixtures with a source/canonical semantic comparison and `parse -> IR -> XML -> parse -> IR`: the canonical form must be a fixed point and supported payloads must remain present. The M2 fixture makes native defaults explicit with multiple layers and an omitted view. Every output is also loaded and saved by `ipetoipe` 7.2.30.

Native reload is an acceptance check, not the final serializer: M1 already measured that Ipelib normalizes defaults and may remove `x-*`. In accordance with ADR-0003, the server therefore preserves its own lossless IR/XML and uses the native runtime for probes and sensitive mutations, without blindly replacing the canonical file with native output.
